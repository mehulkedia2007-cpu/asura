# P5 — interview intelligence, placement prep and coaching

Completed 2026-09-26 within the build plan §13 cut lines. P6 remains next.

## Product flow

- `/en/questions`, `/te/questions`, `/hi/questions`: company and exact reported-role search, topic/round/year filters, coverage counts, source dates, refresh, original excerpts and translated practice wording. Every candidate question links its public report. Empty and thin states do not invent hiring facts or reuse a different role's questions.
- `/prep`: paste labeled notice fields, inspect retained source spans, correct missing or ambiguous values, explicitly confirm, then calculate a day-by-day plan. It uses saved path skills and the union of taxonomy requirements and corpus skill topics. Shared match and roadmap functions compute the gaps and prerequisite order; schedule capacity and unfinished hours are explicit. Dates use Asia/Kolkata; the interview day is excluded from study capacity. The on-screen pack can be printed and seeds the mock.
- `/interview`: five questions from adequate company-role coverage, supplemented by the goal's skill bank. An optional live-job lookup anchors the fifth question to an unflagged lead. If none is supplied or found, that limit is visible. Browser interim speech and MediaRecorder audio feed the existing final-ASR adapter; the user reviews and confirms the transcript before grading. Typed answers work too. History carries quote highlights, STAR cue coverage, quantifiers, filler rate, keyword coverage when a JD is present, duration and word rate, plus one weakest-STAR follow-up prompt.
- Anonymous session IDs act as capabilities. History is held in Postgres, inaccessible after 24 hours, and can be deleted immediately. New-session creation removes expired rows. Answers lock the session row: replaying or racing the same question does not advance twice. Raw audio is not retained by this feature.
- The agent exposes `get_company_questions`, `build_prep_pack`, `start_interview`, and `interview_feedback`. It cannot supply its own notice confirmation or invent a learner transcript to grade. Interview source cards pass the existing citation/prose checks. Health now counts all ten actual agent tools.

## Corpus and guards

`data/companies.yaml` contains 60 general discovery entries, **not verified recent recruiters for a particular college**. No college list was supplied. The reviewed corpus has 11 questions from four public candidate reports: TCS Prime (five), Infosys Specialist Programmer (six). Source-update dates are in 2024; they are not predictions of 2026 rounds. Role aliases preserve this distinction. Telugu/Hindi question wording stays beside the original English evidence span. Source translations have not had an independent native-speaker review.

The source registry permits GfG interview reports and public GitHub Markdown/text. Fetches obey robots, use a bounded response and one-second spacing, and reject redirects and other hosts. The refresh verifies retained excerpts; temperature-zero extraction uses the existing provider chain/cache and rejects non-source questions, unknown skills, contact fields and excess excerpts. Each registered report has a maximum 25-word excerpt budget across the selected records. Refresh preserves prior dates when a source fails. Five reviewed TCS records refreshed successfully from two live pages, without changing their source-year claims.

Migration `0007_p5_interviews` adds filtered question storage with pgvector and session persistence. Search and cosine dedupe use deterministic **256-dimensional hashed lexical features**, not learned semantic embeddings; this limitation is material. A 0.92 cosine threshold folds same-company/role duplicates and preserves their source references. The reviewed snapshot remains available during a DB outage; its storage origin and dates are returned. The generic GitHub adapter is available, but no GitHub evidence is seeded.

The feedback guard requires a nonblank verbatim quote, an allowed computed finding, a valid source/severity, and no forbidden promises or praise. A quote cannot license an unrelated model finding. Default feedback uses reviewed templates. Optional `use_model: true` on the feedback API admits only computed findings, permits one rewrite, then falls back to templates. It never publishes the model's unconstrained prose. Lexical STAR indicators are not semantic grading or an ability/personality assessment. Specificity in the report means valid-quote coverage, not human-rated coaching usefulness.

## Applied cut lines and limits

- Source breadth narrowed to the GfG/GitHub lane; no AmbitionBox, LeetCode Discuss or arbitrary blog crawling.
- Notice intake is **paste-only**, using labeled lines. PDF/photo/OCR and general free-form notice interpretation are not implemented. Contact/person clauses and phone/email spans are removed from retained fields; this is a conservative parser, not universal PERSON recognition. The original pasted notice is cleared after extraction.
- Prep export is **on-screen plus browser Print**, not a generated one-page PDF.
- Coach metrics are **text-based**. Librosa pause/pitch bands are not implemented. Recorded duration supports word-rate calculation; typed edits clear that duration. Follow-up prompts are available, without a separate scored follow-up turn.
- Current taxonomy coverage still limits skill mapping. The four report sources and golden sets are a small development corpus. The tests below are regression evidence, not independent field validation, Telugu ASR accuracy, or placement-success estimates.

The P5 golden runner passes retrieval recall@5 1.0 (10 cases), notice field accuracy 1.0 (20 synthetic cases), feedback must-mention recall 1.0 (8 cases), valid-quote coverage 1.0, and zero violations across 116 feedback adversarial checks. Notice privacy and corpus no-data fixtures also have zero violations. The existing P3 precision@5 gate remains 0.805.

Local Postgres migration/seeding and session concurrency, history isolation, expiry and deletion passed. Chrome completes the source → confirmed notice → prep → five answers flow in all three languages, reloads history, deletes it, and checks mobile overflow. Screenshots were visually inspected. The recording regression uses an in-browser Web Audio generated stream and a stubbed ASR response to verify audio capture and the mandatory transcript-confirmation step; it does not establish real microphone transcription quality. Native synthetic microphone acquisition stalled in this environment; the UI now provides cancellation and a 20-second timeout for unresolved permission/device requests.
